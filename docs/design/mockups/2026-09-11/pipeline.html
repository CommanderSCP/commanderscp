What the pipeline view adds

  1. The connector carries the gate, not decoration. Between waves sits the one fact that decides whether anything moves: fan-in satisfied · 9 of 9, approval required · 1 of 2, or a blocking policy. Your PromotionArrow already paints open / blocked / approval / pending — this gives it a number.
  2. Density switches by Category. Wave 0's nine build artifacts are the compact line — reticle, name, Type, four check pips, status. Waves 1–2 use the full card, because an infra plan or a frozen config target is where you actually stop and read. That answers the density question from earlier: both, chosen per wave.
  3. Type is text throughout — image, chart, npm, maven, python, go, rpm, deb, vm-image, infrastructure, configuration — with the Category as the wave's own eyebrow. All eleven appear here.
  4. The artifact chip shifts with Category. A build target shows nothing (its artifact is the output); an infrastructure target shows the plan and its add/destroy counts; a configuration target shows the deployed image. Same slot, Category-appropriate content.
  5. Check pips survive the compact line. Four dots in fixed order, so even at one line per target you can see which build has no post-deploy gate.
