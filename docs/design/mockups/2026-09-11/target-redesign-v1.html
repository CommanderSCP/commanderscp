The four hooks — always all four, always this order

post-merge Gates entry to wave 1.
post-deploy Gates promotion out of a wave. Optional stage; absent means every wave.
continuous The canary probe whose latest result holds. Value shows evidence age against maxAgeSeconds.
bake Quiet window that must pass alarm-free before the wave may exit.

Two absences that must not look alike

continuous— Not bound — no such hook is declared. Structural absence: grey, dashed, em-dash, tooltip. Never amber — nobody promised this check.
continuousno evidence Bound but unverified — a probe exists and its newest evidence is older than maxAgeSeconds. Amber, because someone promised this check and it has gone quiet.

Why it is built this way

  1. Four fixed slots, always rendered, always in pipeline order — post-merge, post-deploy, continuous, bake. Fixed position is what makes the column scannable: the third slot is always the canary, so an unbroken run of dashed thirds down the wave is instantly "nothing here is being watched".
  2. Absent and unverified are drawn differently, because your model already separates them. maxAgeSeconds's own comment says stale evidence is "ABSENT, not stale-pass and not fail" — but a bound probe going quiet is still a thing an operator should chase, so it is amber; a hook nobody declared is grey. Painting both amber would recreate the wall-of-amber §1.5 explicitly fixes.
  3. A wave-level count — "3 without a canary" in the header — so the gap is visible before you scan a single row.
  4. "not run" is distinct from "—". On the untouched target the two gated hooks say not run (they exist, nothing reached them) while the unbound two say —. Same grey, different word: one is waiting, the other will never happen.
