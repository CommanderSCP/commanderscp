Three things can originate change — only one is drawn above

Source mapping — a git repodrawn above
Always git: github, gitea or gitlab. It is never an image or chart registry — a registry is where artifacts land, not where change comes from. What the repo holds is exactly what the routing Type declares: chart = chart sources, image = code that builds an image, infrastructure = Terraform, configuration = deploy config. That is the "what kind of repo" answer — it is the Type, worded.
Registry — where artifacts landdifferent tile
An execution-system object reached by a publishes_to edge, with properties.kind — gitea, harbor, ecr, … This is your image repo / chart repo. Note the kind is a free string, not a closed enum, so a tile cannot switch on a fixed vocabulary. It also carries state: declared | ambiguous | none — ambiguous meaning more than one publishes_to edge, which a tile must show rather than pick a winner from.
Dependency line — an upstream indexdifferent tile
The alpine:1.2 → 1.3 case. A public index polled for a major line's head — genuinely a source of change, and the only one that is not yours. Modelled separately in dependency_lines, and dormant on this instance.

When two mappings could match

Push to jag8765-personal/agentkit · infra/vpc/main.tf · refs/heads/dev
1 infra/** · refs/heads/dev → agentkit-vpc most specific · wins
2 infra/** · any ref → agentkit-vpc ref is broader
3 ** · any ref → agentkit catch-all
Specificity is resolved on all three globs, not just the path. Showing the losers is the point: a mapping that never wins looks identical to one that does not exist, until you see it ranked.

What the tile encodes

  1. All three globs, always, in routing order — repo, path, ref. A mapping is a three-part rule and hiding the part that happens to be broad is how you end up debugging the wrong one.
  2. "any ref" is worded, not em-dashed. refPattern: NULL means match every ref — a rule, not a missing value. An em-dash there would say "unset" about the single most consequential default in the routing table.
  3. Type is labelled "declared". Your own schema comment is emphatic: it is "NOT inferable from sourceKind — a GitHub Actions run can apply Terraform or ship an app — so the operator declares it per mapping." Rendering it as a bare fact would imply derivation.
  4. Precedence shows the losers. When several mappings match one push, the ranked list makes the near-misses visible; an unranked view makes a never-winning mapping indistinguishable from one that does not exist.
  5. "no event, ever" is amber-dashed, not grey. A mapping that has never fired is a rule someone wrote that has never been true — worth noticing, unlike a structural absence.
Grounding. The mark and tile are proposals; the three tiles are fixtures. On this instance source_mappings, config_source_stacks and config_source_sync_queue are all zero rows, which is why the empty state is included — it is the state you would actually see. Note also that config-source is a registered object type with no instances, so "Sources" may need to cover both it and source_mappings; I have drawn the mapping, not the config-source, and those may want different tiles.
