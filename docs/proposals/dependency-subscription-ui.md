Semantics the UI must carry (ADR-0032 + code): the merge is `enabled = instance.unlocked && anyEnable && !anyDisable` — **a disable at any tier wins**, tier labels are explainability only; four `reason` values `enabled | instance_locked | disabled | not_enabled` (order of report `instance_locked > disabled > not_enabled`); `granularity`/`delivery` are meaningful **only when enabled**; `auto_merge` needs unanimity among enabling contributions and the *first* dispatch is always a pull request; an `ignored` contribution (`malformed | condition_unevaluable`) is **recorded, not dropped** — a UI that hides it hides exactly the opt-out that silently did not apply; `latestVersion: null` = *not observed*, never *nothing newer*; `resolvedVersion: null` = *manifest pins none*; coordinates travel **verbatim** (`@acme/lib`); the resolution route resolves **as the caller**, the jobs as `SYSTEM_ACTOR_ID`; **never recompute the AND client-side** (the resolver says so explicitly). Third-party polls and bump dispatch run **only on a declared commander** — an outpost (or an undeclared role) has inventory + enablement and *no* head advances, *no* bumps.

## 2. What the UI is (owner's words, mapped)

Teams subscribe to a **major line**; updates within it arrive as automatic code changes at a chosen granularity (patch | minor_and_patch), delivered as a pull request or auto-merge; container base images count; enablement is a chain (instance **unlocks**, org/domain/service/component **enable**, teams **opt out** down to a line); ingestion runs only for enabled components. So the UI has to answer, per component: *what do I depend on, what is the head of each line, am I subscribed and why, what has been bumped, and can I enable / opt out here.*

## 3. Read surface first (API → SDK → CLI → IaC), all additive

### 3.1 `GET /components/{idOrUrn}/dependency-inventory` (name: §8 Q1)
`object:read` at the component (same as the resolve route — **not** at the org, so a component-scoped viewer can read it). Response (paged `limit`/`cursor`, default 100):
```
{ component: {id, name},
  ingestion: null | { lastAttemptAt, source, outcome, rowsWritten, manifests[] }        // M21.7 stamp when landed; null = not recorded (NEVER "no dependencies")
  lastIngestionDecision: null | { decisionId, firstObservedAt, manifestPathsRead[], manifestPathsAbsent[], skipped[] }  // what exists TODAY
  componentGate: { reason: "enabled"|"instance_locked"|"no_enabling_contribution", contributions[] }   // the SAME function ingestion uses (resolveComponentIngestionGate), never re-derived
  rows: [ { line: {id, ecosystem, coordinate, major, tagPattern?},
            manifestPath, declaredVersion, resolvedVersion, resolvedDigest, observedRepo, observedRef, observedAt,
            head: { latestVersion, latestDigest, latestObservedAt },                     // nulls = not observed
            producer: null | { objectId, name },                                          // declared only; null = third-party OR undeclared (say which? — cannot: declared-null is the stored fact)
            subscription: { enabled, reason, granularity, delivery, contributions[] } } ],  // gatherSubscriptionCandidates ONCE per component + merge per line (listSubscribedComponentLines' internals minus its enabled-only filter)
  nextCursor }
```
`manifestPath` stays a row key (one line from two manifests is two rows — it is in the PK for that reason). No client-side AND, no derived tiers.

### 3.2 `GET /components/{idOrUrn}/dependency-bumps`
`object:read` at the component. Rows from `dependency_bump_authorships` (its `org_subject` index leads with the component) joined to the change and the newest `dependency_bump_merge` Decision: `{ changeId, changeName, line, manifestPath, fromVersion, toVersion, repo, baseBranch, authoredRef, pullRequestNumber, pullRequestUrl: null (not stored — see §8 Q4), headCommit, dispatchedAt, mergedAt, delivery, deliveryReason, merge: null | { verdict, decisionId, evaluatedAt } }`. The change's `state` is not progress (bumps sit at `proposed`); merge state comes from the Decision/`merged_at` only.

### 3.3 SDK / CLI / IaC
- SDK: `client.dependencySubscriptions.inventory(componentIdOrUrn, {limit, cursor})`, `.bumps(componentIdOrUrn, …)` — generated from the schemas.
- CLI: `scp dependency-subscriptions inventory --component <id|urn> [--ecosystem]` (columns: ECOSYSTEM · COORDINATE · MAJOR · MANIFEST · DECLARED · RESOLVED · LATEST · SUBSCRIPTION · REASON) and `… bumps --component` (COORDINATE · FROM → TO · PR · DISPATCHED · MERGED); the closed-list test grows by two read verbs (still no subscribe/enable/disable). Fix the pinned help text that names a non-existent `scp policy create` → `scp policy register` (§7, with the M21 session).
- IaC: `Policy = defineResourceConstruct("policy")` in `@scp/iac` (one line + export + test) so a subscription policy is first-class in a stack: `new Policy(stack, "checkout-deps", { name, properties: { enforcement: "advisory", scope: { objectRef }, effects: [{ dependencySubscription: { enabled: true, granularity: "minor_and_patch" } }] } })`. No schema change (the manifest already accepts `typeId:"policy"`).

### 3.4 Review notes (M21.7 session, 2026-08-16)
- **`head.*` has a data source**: `dependency_lines.latest_version / latest_digest / latest_observed_at` exist (0061:217-221) and `recordDependencyLineHead` writes them on every poll — a `restated` (unchanged) head is `moves: true` and updates `latest_observed_at = now`, so the column means **last observed**, not last changed. The poll *Decision's* timestamp would mean "last changed" (persist-on-change) — the UI never derives "last checked" from it. `latestVersion` and `latestObservedAt` stay separate nullable fields.
- **One resolution core**: the inventory route and `listSubscribedComponentLines` must call one shared function with an `includeDisabled` parameter — not "the internals minus a filter". If the build forked it, the fix round unforks it.
- `componentGate.reason` (`enabled | instance_locked | no_enabling_contribution`) is nested under `componentGate` precisely so it is never confused with a row's `subscription.reason`; the CLI/web must switch on the right one.
- **`POST /policies` gate ordering (measured, M21.7-owned)**: `policy:write` is authorized at `resolveDomainId(body.domainId) ?? org` BEFORE the scope-authority check, and any org object is accepted as `domainId`. The UI therefore sends `domainId` = the component itself (§4.2) — not the containment domain (refuses a component-bound binding) and not omitted (refuses everyone below the org root). The pin stays measured-not-fixed; its 403-without-`domainId` case is the tripwire for anyone landing an ergonomic default (authorize a bounded `objectRef` at-or-above the ref) without an owner decision — that default splits authorized scope from written containment.
- **A parallel read that is pending or failed is never painted as an answer** (fix round): the unlock and bumps queries resolve independently of the inventory, so the view receives each as `pending | error | ok` — pending → skeleton, error → `—`/amber `unknown` with the diagnosis, and only a successful zero-row bumps read says "No bumps yet.".

## 4. The UI

### 4.0 Commander-only (owner rule, 2026-08-17)
The owner ruled that **dependency automation happens only at the commander**: its purpose is to pull from *public* registries to bump the global repos (Python libraries, CDK, base images…), and outposts receive the resulting change down the promotion pipeline the commander manages — an outpost never originates a bump and holds no inventory. Server consequence (M21.7's, confirmed with the owner by that session): inventory ingestion and internal-release detection gain the same commander-only fail-closed guard the poll and bump dispatch already have; the backfill route refuses on a non-commander; ADR-0032 §7c clause 3 is amended (outpost-only IaC/CaC repos are out of scope for subscriptions by design). UI consequence (this proposal): the **Dependencies tab is offered on the commander site only** (read from the install-time `instanceRole`, like Campaigns/Graph in the nav); a direct `/components/{id}/dependencies` URL on any other role renders a stated pointer — "Dependency subscriptions are managed at the commander" — and issues no reads; the read routes stay registered on every role (read-only). §4.1's "present on both sites" and §4.4's outpost sentence are superseded.

### 4.1 Where: a **Dependencies** tab on the component page
`Infrastructure · Delivery · Dependencies · Settings` (fourth `createRoute` under `componentDetailRoute`, testid `component-tab-dependencies`; the e2e pin on `component-tab-settings` stays). Not on the service board this round. Present on **both** sites; on an outpost the bumps section states "bumps are dispatched by the commander" (read from `instanceRole`), never an empty table that looks up to date.

### 4.2 Header strip — the chain, honestly
- **Instance:** `unlocked by the platform operator · <updatedAt>` | `locked — set by the platform operator` | `locked (never set)` (three states from `{unlocked, updatedAt}`; `updatedAt: null` ≠ re-locked). **Read-only in the tenant UI** with the CLI pointer (`scp dependency-subscriptions set-unlock --unlocked`) — the write needs a deployment secret (§8 Q2).
- **This component:** from `componentGate` — `enabled via <source> (<tier>)` | `not enabled — no enabling policy at any tier` | `instance locked`; contributions open the same explain dialog as a row.
- Offer-the-write (M16.3): **Enable for this component** (authors an `objectRef`-scoped policy `enabled:true` with granularity/delivery pickers, `enforcement:"advisory"`) — rendered always; the server's refusal is rendered verbatim (403 → "needs `policy:write` at this component (or above)"; 409 delegation → message + `WhyLink(decision_id)`; 400 group → cannot happen from this form because the form never offers group). **Both forms send `domainId` = the component's OWN id** (fix round, 2026-08-17, from the M21.7 measurement in `governance/policy-write-gate-ordering.integration.test.ts`): `objects.domain_id` is a general containment-parent pointer (any org object is accepted), `POST /policies` authorizes `policy:write` at `domainId ?? org` and RBAC expands upward, so a component-bound, domain-bound and org administrator all pass, and the written policy is contained by the component — where its team can PATCH/DELETE it (those routes authorize at the policy's own id). Sending the containment domain would refuse the component-bound team; omitting it refuses everyone below the org root. Naming the permission is required by the M16.3 rule; the SPA cannot pre-check it (no permission introspection).

### 4.3 The table — one row per declared line × manifest
`dependency` (coordinate, verbatim, mono) · `line` (ecosystem · major) · `manifest` (path) · `declared → resolved` · `latest` (`latestVersion` or `—` "not observed yet") · `subscription` (Badge: `enabled` success · `opted out` neutral · `not enabled` neutral · `instance locked` warning; **`ignored` contribution present → amber `unknown`-tone pill "opt-out ignored"** with the reason) · `Why` (dialog listing `contributions[]` by tier, source, contributed, selector, granularity/delivery, ignoredReason) · row action **Opt out** (authors an `objectRef`-scoped policy `enabled:false` with the effect-level line selector — *never* a scope selector; refusal rendered) and, when the row's only enabler is an org/service policy, no "enable" per line (the chain does that; explain instead). `producer` shows `internal (<name>)` only when declared; otherwise nothing is inferred.
- Empty states, keyed on `ingestion` (M21.7) then `lastIngestionDecision`: **never attempted** → "Not ingested yet — the inventory is read when a release is accepted or an operator runs `scp dependency-subscriptions backfill-inventory`" (+ "ingestion runs only for enabled components" when the gate is not enabled); **ok + 0 rows** → "No dependencies declared — read N manifests at `<ref>`"; **unreadable/partial** → the file list with each outcome; **stamp null and no decision** → "Ingestion status not recorded" (amber `unknown`), *never* "No dependencies".

### 4.4 Bumps section
Table from §3.2; PR shows `#n` (link only if a URL exists — none today, §8 Q4); the Merge cell is READ, never inferred: `merged <date>` / the merge Decision verdict with `WhyLink` / `not merged` when a PR number is on record and no merge is (the server never observes a close-without-merge, so `open` was a claim it cannot make — replaced in the fix round) / `—` when no pull request has been reported yet. Outpost: the sentence above instead of a table.

### 4.5 Fixture / mockup honesty
The review pair cannot ingest real manifests (its repos are `.invalid`, the github binding is inert, and the plugin host will not read them), so the tab will show the **enablement chain + writes + honest empty inventory** — not rows. The fixture adds: `SCP_OPERATOR_TOKEN` on the commander's restart recipe + `PUT unlock` (via SDK with the token), one enabling policy for `checkout-api` (component scope; the fixture's admin holds `policy:write`), one opt-out policy for a named line (so the `Why` dialog has content), and no fake rows. A server-reachable fake git provider (the e2e compose has a `fake-argocd` precedent) is a follow-up if the owner wants rows in the mockup.

## 11. Merge note (2026-08-18) — what landed when this branch met M21.7 / ADR-0032 §7d–§7e

The shapes above were written against the 2026-08-16 agreement; the merged tree is the authority and differs in four places, all additive on the wire:

- **`ingestion` is read for real** — `findIngestionStampByComponent` (`dependency_ingestion_stamps`, migration 0065), in the same transaction as the rows. `null` = **never attempted** (the repo's one reading of a missing row). `manifests[]` entries carry `repo` (the stamp is merged **per repository** by its writer), `rows` and `at` beside `path`/`outcome`/`detail?`; the stamp carries a top-level `detail: string | null`. The "not recorded" wording survives only as the UI badge for *stamp null and no Decision* ("not recorded — never attempted").
- **Both read responses carry a REQUIRED `dependencyManagement`** (`DependencyManagementSchema`, computed by `dependencies/commander-only.ts`'s one predicate). `managedHere: false` ⇒ the rest of the envelope is not to be interpreted; the routes still 200 with unchanged RBAC. The web renders the "managed at the commander" pointer off the wire (beside the role gate); the CLI prints one line and skips the table.
- **`producer` is read from `dependency_line_producers`** (ADR-0032 §7e — the declaration's grain is the *coordinate*; `dependency_lines.produced_by_*` was dropped in 0072). Wire shape unchanged: `{ objectId, name } | null`.
- **`pullRequestUrl` is READ** off `dependency_bump_authorships.pull_request_url` (migration 0066 — the provider's own URL, stored by `recordBumpPullRequest`); `null` when none was recorded; still never composed. The web PR cell links to it (external, `noopener`); the CLI prints it in place of `#n`.
